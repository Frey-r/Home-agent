## 1. Objetivo y Alcance

Implementar el hito **M2a** según la sección 6 de [docs/arquitectura.md](../arquitectura.md) y el [ADR-0008](../adr/0008-llmkit-formato-neutro-adaptadores-openai-anthropic.md):
Construir el paquete y módulo Go compartido `llmkit/`, que trata al proveedor de LLM como una **commodity intercambiable**:
1. Formato neutro canónico (`contracts/schemas/llm.v1.json` y tipos Go en `contracts/`).
2. Adaptador de wire `type: openai` (compatible con OpenAI, Azure OpenAI, NVIDIA NIM / Nemotron cloud, Ollama local, Groq, DeepSeek, Workers AI).
3. Adaptador de wire `type: anthropic` (compatible con Claude, MiniMax).
4. Streaming Server-Sent Events (SSE) normalizado a eventos neutros tipados.
5. Contabilidad unificada de tokens y prompt caching en `Usage`.
6. `Router` con cadena de fallbacks automática ante 429, 5xx y timeouts.
7. Simulador hermético de pruebas `llmtest.Server` y suite de conformidad común a ambos adaptadores.
8. Smoke test opcional de integración contra endpoints reales compatibles (como Nemotron cloud u Ollama local).

## 2. Requisitos Previos y Contexto Técnico

- **Go version**: 1.27.0 en `go.work`.
- **Race detector**: CGO habilitado solo para pruebas con MinGW-w64 (`dev/scripts/test.ps1`).
- **Determinismo**: pruebas unitarias herméticas sin conexión a internet mediante `httptest.Server` con fixtures de wire capturadas de OpenAI y Anthropic.
- **Cero fugas de goroutines**: verificación obligatoria con `goleak`.

---

## 3. Estrategia de Pruebas Primero (Strict TDD)

Toda funcionalidad debe comenzar con pruebas automatizadas en rojo antes de escribir el código de producción.

### Suite de Conformidad Común (`TestConformance_Common`)
- [ ] `TestConformance_SingleTurn`: envío de prompt de texto y recepción de respuesta textual normalizada.
- [ ] `TestConformance_MultiTurn`: conversación de múltiples turnos con roles preservados.
- [ ] `TestConformance_ToolCalling_Simple`: definición de una tool y generación de `tool_call` con argumentos válidos.
- [ ] `TestConformance_ToolCalling_Parallel`: emisión de múltiples `tool_calls` en un único turno.
- [ ] `TestConformance_ToolResult_Resume`: envío de `tool_result` y continuación fluida de la respuesta del asistente.
- [ ] `TestConformance_Streaming_Text`: streaming SSE con acumulación fluida de fragmentos de texto.
- [ ] `TestConformance_Streaming_ToolCalls`: streaming SSE con ensamblado robusto de argumentos de herramientas fragmentados.
- [ ] `TestConformance_Usage`: extracción exacta de tokens (`input`, `output`, `cache_read`, `cache_write`).
- [ ] `TestConformance_StopReasons`: mapeo canónico de `end`, `tool_calls`, `max_tokens`, `refusal`, `error`.
- [ ] `TestConformance_ContextCancel`: cancelación de contexto que aborta la llamada HTTP y cierra streams limpiamente sin goroutine leaks.

### Router y Fallback
- [ ] `TestRouter_PrimarySuccess`: llamada exitosa en el proveedor primario sin consultar fallbacks.
- [ ] `TestRouter_FallbackOn429`: conmutación automática al fallback ante HTTP 429 (rate limit).
- [ ] `TestRouter_FallbackOn5xx`: conmutación automática al fallback ante HTTP 500/502/503/504.
- [ ] `TestRouter_FallbackOnTimeout`: conmutación automática si el primario excede el deadline de contexto.
- [ ] `TestRouter_NoFallbackOn400`: error de cliente (400, 401) falla de inmediato sin intentar fallbacks innecesarios.
- [ ] `TestRouter_AllFailReturnsCompositeError`: reporte detallado de error si todos los proveedores fallan.

### Smoke Tests Opcionales (Reales)
- [ ] `TestRealLLM_OpenAICompatible`: validación opcional en vivo contra endpoint real (Nemotron cloud u Ollama) cuando se proveen credenciales en variables de entorno.
